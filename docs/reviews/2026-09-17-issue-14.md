# Review: issue #14

Scope: the prefactor for [issue #14](https://github.com/akshaydeshraj/helyx/issues/14), content blocks and stream events for tool calls and thinking. Two-axis review with sub-agents before the first commit.

## Findings

- The ticket said "tool result block". ADR 0001 makes tool result a message role with `tool_call_id`, `tool_name`, and `is_error`, and lists four blocks: text, thinking, tool call, image. The ADR wins. The ticket also said the ADR names the fields; the feature doc does. Both citations fixed in the code and devlog.
- `message_update` data used `delta` for text and `thinking_delta` for thinking. Fixed: `text_delta`, `thinking_delta`, `tool_call`. No client existed to break.
- A malformed stream event, such as a non-binary delta or a tool call that is not a struct, crashed the session. Fixed: the Task checks each event and turns a bad one into `{:error, {:bad_stream_event, event}}`, so the turn fails and the session lives. Covered by a test.
- "Chunk" and "block event" wording replaced with "delta" and "stream event" to match the glossary.
- `Image` has no stream event because providers do not produce images. Stated in the Provider docs.

## Not changed

- `is_error: false` is the default on every message, not only tool results. Harmless.
- The text and thinking clauses of the block accumulator are structurally alike. Four lines each; a generic version would hide the struct types.

## Validation

- `mise exec -- mix precommit`: fourteen root tests and four plugin tests, 0 failures. Every pre-existing test is unchanged except the two Fake provider assertions that read the renamed `text_delta` key.
