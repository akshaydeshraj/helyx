## Follow-up: external (Codex) review of PR #54

Two confirmed findings, both fixed, shipped as their own commit.

1. **The hands could KILL the watchdog before it reaped its command.** With a TERM-ignoring command, the cancel sweep KILLed the command group and the watchdog group in one batch at the same deadline. Where PID 1 does not reap orphans, the unreaped zombie would hold the group, and the stuck set, forever. Fixed structurally: `register_group/2` carries a kind, and the hands sweep in two phases — command groups first, then watchdogs, which get a `wait_ms` window to exit by themselves before the fallback KILL. A watchdog is now KILLed only after every command group swept with it is gone or stuck.
2. **The session swallowed exits from linked processes that are not provider Tasks.** A crash of the sessions Registry partition left the session alive but unreachable (`Session.pid/1` nil) — a regression against the non-trapping base. Fixed: the session tracks provider Task pids in a `provider_pids` set and stops on any other exit. An aborted Task's pid stays in the set, because `Task.shutdown` unlinks before killing but does not flush an already-queued exit and the ordering against the DOWN is undocumented; the bounds table records the one-pid-per-abort growth as accepted for checkpoint one.

Ship round on the fixes (first round, full):

- **Simplify**: three findings, applied — a misplaced test that stole another test's `@tag :capture_log`, a wrapper map around `split_kinds/1`, a moduledoc wrap. Confirmed `provider_pids` and the two-phase sweep as the right altitude.
- **Standards**: no hard findings; judgement calls (twice-used sweep sequence at the threshold, `if` over a head match where `MapSet.member?` cannot be a guard) accepted.
- **Spec**: three doc gaps, applied — a bounds row for the `provider_pids` growth, one clause making the watchdog phase's two 5 s waits explicit, and the `register_group/2` doc corrected to "every command group swept with it is gone or stuck" (on cancel the sweep spans every cancelled call).
- **Failure-path**: both first reproductions pass; hunts on late `:normal` exits, back-to-back turns, abort-then-exit, stuck commands with watchdogs, watchdog-only calls, mixed-kind cancels, and the `clear_stuck/1` re-KILL found nothing. Real-OS bash suite passes.

The step-2 changes were documentation only (two table rows and one `@doc` sentence), so the loop ends without another code round.

## Standing skip rationales (design calls, recorded once)

- Blocking `select` + SIGCHLD in the watchdog rejected as racy (a signal before select blocks is lost); the 50 ms poll tick is deliberate.
- `read_marker` tolerates a stream that does not start with the marker, so a perl failure surfaces as output instead of hanging.
- The `check/1` seam on the bash tool stays for the acceptance test of a perl-less system.
- Per-owner Task.Supervisors are out of scope; Core's one supervisor with links does the ownership work.
- A zombie-aware `alive?` predicate was rejected for portability; the watchdog's blocking reap makes it unnecessary.
- Chat and quit while a group is stuck are structurally unaffected (the stuck set gates only tool calls); no extra test.
