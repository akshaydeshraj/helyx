# Review: issue #2

Scope: the implementation of [issue #2](https://github.com/akshaydeshraj/helyx/issues/2), the root project and the Fake provider plugin, before the first commit.

Two passes ran. The first was a manual pass with reproduction code outside the repository. The second was the two-axis code review (standards and spec) with sub-agents. The findings overlap; they are merged here by severity.

## Findings

### P1: Required interface checks depend on module load order

Location: `Helyx.Core.Plugins`.

`known_interfaces/1` scanned `:code.all_loaded()`. In a fresh Mix process `Helyx.Provider` is not loaded, so Core accepted `plugins: []`. After `Code.ensure_loaded!(Helyx.Provider)` the same call returned `{:error, {:missing_plugin, Helyx.Provider}}`. The root test for a missing required plugin failed on most seeds. Both review passes found this.

Resolution: fixed. Core takes `interfaces:` and defaults to `Helyx.Core.interfaces/0`, which lists the bundled interfaces. Core checks that list plus every interface a plugin implements. A module in the list that is not an interface is `{:error, {:not_an_interface, module}}`. Tests cover the default, an explicit list, and a plugin interface outside the list.

### P1: An old task failure can end the current turn

Location: `Helyx.Session`.

The abnormal `:DOWN` handler accepted every task reference. A provider that emits `done` and then fails in stream cleanup made the session end the next turn with that failure, or crash when no turn was active.

Resolution: fixed. The session matches replies and `:DOWN` messages against the current task's reference and drops the rest. On `done` it demonitors the task and flushes. `Helyx.SessionTest` covers a task that exits after `done`.

### P2: A stream that ends without a terminal event leaves the session busy

Location: `Helyx.Session`.

A task reply was discarded without checking whether the turn had ended. An empty stream left `turn` set, clients got no terminal event, and every later prompt returned `{:error, :turn_running}`.

Resolution: fixed. A reply from the current task with the turn still open ends the turn with `agent_end` carrying `error: :stream_ended`. The provider docs state that a stream must end with `done` or `error`. `Helyx.SessionTest` covers the empty stream and a later prompt.

### P3: Standards

- Public functions without `@doc`: `Message.user/1`, `ModelRef.parse/1`, `ModelRef.to_string/1`, `Fake.child_spec/1`, `Core.start_link/1`, `Core.child_spec/1`. Fixed. `Session.child_spec/1` and `Session.start_link/1` are `@doc false`; the supervisor calls them.
- Bare maps with a known shape for session state, the turn, and the partial message. Fixed with `Session.State` and `Session.Turn` structs. `Interface.declaration/1` still returns a small map; it has two fields and one caller.
- `Helyx.Message` moduledoc used "entry", which the glossary reserves for one session file line. Fixed.
- `docs/features/coding-agent.md` said the turn Task runs under the session; the code runs it under Core's task supervisor with a monitor. The doc now says what the code does.
- `Helyx.Core.Plugins` called its map a registry, which clashed with the two Elixir `Registry` processes Core owns. Renamed to table.
- `ensure_partial/1` emitted an event under a name that did not say so. Renamed to `start_assistant_message/1`.

### Spec

- The user message also gets `message_start` and `message_end`. Issue #2 lists seven event types; the emitted sequence is ten events. Kept, and recorded in the devlog, so a second client can render the user message from the stream alone.
- `Session.prompt/2` returns `{:error, :turn_running}` while a turn runs. Kept. The steer and follow-up queues in later tickets replace this branch.
- `Session.start/2` raises when `:model` is missing. Kept. A missing required option is a caller bug, not a runtime failure.
- The IEx recipe from the acceptance criteria needs the Fake plugin on the code path. Run it from `plugins/provider_fake` with `iex -S mix`.

## Not changed

- The `precommit` alias and `cli/0` are repeated in the root and the plugin `mix.exs`. Two copies is fine; a shared Mix config can wait until a third plugin exists.
- `Helyx.Provider.Fake` names its scripts Agent per Core instance. The plugin has no other handle to its state, so a name is necessary here.

## Validation

- `mise exec -- mix precommit` passed with Elixir 1.19.5 and OTP 28.5.0.6: eleven root tests and four plugin tests.
