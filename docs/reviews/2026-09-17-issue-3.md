# Review: ticket #3, hands and the four tools

Three axes on the working tree before commit, per `/ship`. Findings and their resolution.

## Standards

- `Helyx.Hands` kept its state in a bare map. Fixed: a `State` struct.
- `Helyx.Tool.truncate/2` used a count of `0` as the "everything fits" sentinel. Fixed: `:all`.
- Comprehension in a `case` head in `end_turn/2`. Fixed: `calls` is bound first.
- `tool_execution_update` from the feature doc is not emitted. Not in this ticket; no tool streams output yet.
- Repeated path schema and file error strings across the three file tools. Left as is; a helper lands with a fifth site.
- `Fake.run_tool/3` is a test harness in a provider plugin. Left as is; it is the one place the four plugin tests share, and the ticket requires the session seam.

## Spec

- No node loads all four tools together, so the IEx walkthrough in the ticket body needs a product Mix project. Follow-up: the app ticket adds `apps/coding_agent`; the acceptance criteria are all met by tests.
- The process group needs perl. Without perl the command runs in the node's group. Accepted and commented in the tool.
- `offset` on read, `mkdir -p` on write, `(no output)`, and stdin from `/dev/null` are not in the ticket. Kept; recorded in the devlog decisions.
- **Truncation bypassed by one oversized line.** `truncate/2` returned the full text when the first line in scan direction was over 50 KB. Fixed: the line is cut to the limit and the result says it shows one line. Test added.
- **A dead tool Task hung the turn.** The hands did not monitor the Task. Fixed: `async_nolink` with a `:DOWN` handler that delivers an error result. Test added with a tool that kills its own Task.
- **Duplicate tool call ids hung the turn.** Results are keyed by id, so the count never matched. Fixed: the turn fails with `{:duplicate_tool_call_id, id}` before any call runs. Test added.

## Failure path

Reproduced with throwaway tests under `.scratch/review/`, all deleted.

- Truncation bypass, dead Task, duplicate ids: as above.
- **A tool call with a non-string name raised in the Task.** Fixed: `consume/3` checks `id`, `name`, and `arguments` shapes; a bad call is `{:bad_stream_event, event}`. Test added.
- **Two tools with one name booted and the last one won.** Fixed: `Helyx.Tool.by_name/1` rejects the duplicate and `Session.start/2` returns `{:error, {:duplicate_tool_name, name}}`. Test added.
- **A bad Fake script item crashed the shared scripts Agent** and lost every script. Fixed: the conversion runs outside the Agent, so only that turn fails. Test added.
- **Bash with a missing working directory** returned exit code 2 instead of an error result. Fixed in the hands, once for every tool. Test added.
- A background child that keeps stdout open holds the call. Documented in the tool; the abort ticket owns timeouts.

## Second pass

Simplify and review ran again on the fixes. Applied: the working directory check moved from bash into the hands, once for every tool; `end_turn/2` lost a helper that carried unused arguments; the Fake script lookup uses `with`. Three simplify agents asked the session to build the tool specs from its own table and drop `Hands.tools/1`. The spec and standards reviewers showed that this contradicts ADR 0003, so the hands resolve their own table from Core and report it, and `Session.start/2` only pre-checks the names so a duplicate is an `{:error, _}` and not a crash of the linked hands during the session's `init`. The hands have no test file of their own; the session tests are their seam. The second failure-path agent stopped on a rate limit; the pass was done by hand and added a clause that drops a stray message to the hands instead of crashing the linked session.

## PR review

One round of human review on PR #18 found four defects. All fixed with tests.

- **Concurrent edits lost changes.** Tool calls from one assistant message ran in parallel Tasks; two edits on one file could overwrite each other. Fixed in the session: the calls of one message run one at a time, in call order, and each result joins the transcript as it arrives. This covers every pair of tools, not only edit against edit. The duplicate call id check became moot and was removed. Ceiling: no parallel read-only calls.
- **Trailing blank lines bypassed truncation.** `truncate/2` trimmed every trailing newline before counting. Fixed: one trailing newline ends the last line; the rest are blank lines that count.
- **A cut line could be invalid UTF-8.** Fixed: the cut backs up to three bytes to a character boundary. Text that was never valid UTF-8 loses at most three bytes.
- **A line exactly at the byte limit was dropped** with a range of `1-0`. The separator was counted even for the last line. Fixed: the separator counts only after a kept line.

Simplify and the three review axes ran on the fixes. Standards: `on_boundary/3` became function clauses with a named retreat and `end_turn/2` binds the turn in its head. Spec: all four defects fixed, nothing weakened. Failure path: a kill mid-sequence, a prompt during a sequence, and a spoofed or stale result all held. Two doc findings: a text of exactly the byte limit plus one trailing newline passes untruncated, which is by design since the terminator does not count, and the `on_boundary` comment said invalid UTF-8 is untouched when it loses up to three bytes. Both docs corrected.

## Greptile

Four findings. Two, concurrent tools and UTF-8 truncation, matched the PR review above and were already fixed. Two were new.

- **Unbounded bash output.** The whole output was buffered until exit. Fixed: only the last four tail limits are kept while the command runs, so `yes` no longer grows the heap. The result then starts with a cut notice, since the model reads the result and not the moduledoc. A timeout stays with ticket #4.
- **Unbounded file reads.** `read` and `edit` called `File.read/1` on any path, so `/dev/zero` blocked forever and a huge file loaded whole. Fixed: `Helyx.Tool.read_file/1` accepts a regular file of at most 10 MiB and both tools use it. The read itself is bounded, so a file that grows after the stat is still rejected. A larger file is an error.

Simplify and the three review axes ran on these fixes. Standards: the bash cap is derived from `Helyx.Tool.max_bytes/0` instead of a restated literal, the error hint no longer names the bash plugin from core, and a checklist line was added. Spec: the cut notice, the amortised buffer copy, and the bounded read came from this pass. Failure path: empty file, FIFO, symlink to a device, a file exactly at the cap, and cuts inside a UTF-8 character all held; two error branches returned a charlist against the `@spec` and now return a string.
