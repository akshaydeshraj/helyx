# Review: issue #12, model switching mid-session

Scope: the working-tree diff for issue #12: `Helyx.Session.set_model/2`, the `model_change` event, the bounds in `Helyx.ModelRef.parse/1`, the `/model` command in `Helyx.TUI`, their tests, and the feature doc.

Bounds sensor, every round: `bounds sensor skipped: TYPESAFE_API_KEY is not set`.

The branch had no commit between rounds, so every rerun round got the whole working-tree diff plus the invariant of the fix, not a diff from the commit before the fix. `origin/master` moved during the work (ticket #51 merged), so from round 2 on the reviewers used `git diff HEAD`, not `git diff origin/master`.

## Round 1 (first round, full: simplify + three axes)

- **Simplify**: 9 findings, 4 applied. Applied: the composer is split into words only when the line starts like the command (the composer is unbounded); `ModelRef.parse/1` uses `Helyx.Message.valid_utf8?/1`; `resolve_model/2` holds the parse and the provider lookup for start, resume, and switch; the TUI notice no longer restates the 256-byte limit. Skipped: one shared test provider (the two live in separate Mix projects); `Session.set_model/2` in a Task (it is the same synchronous call as `Session.steer/2`); dropping the 256-byte bound (the checklist requires a bound); deriving the turn's provider per call (a lookup can fail mid-turn); one `case` for the error texts (function clauses are the repo's form).
- **Standards**: no hard violation. Applied: `resolve_model/2` returns `{:ok, {ref, provider}}`; a comment that said the ref is never echoed now says the notice shows at most the provider id. Judgement calls kept: the `with true <-` chain in `parse/1`, the name `string`.
- **Spec**: no missing or wrong requirement. Fixed: the `cwd` and model on create row (a bad model is now rejected earlier, by the model ref row); "never echoes" weakened to "at most the provider id"; `{:ambiguous_provider, id}` added to the doc; the nil turn id is now asserted for a switch during a turn.
- **Failure-path, confirmed, 2**:
  1. `/model` + U+00A0 + ref was sent to the model as a message: `String.split/1` does not split on a no-break space. Fixed in round 1 with a `\s` regex split; the mechanism was replaced in round 2.
  2. `ModelRef.parse/1` accepts characters that show as nothing (U+3164, U+2800, U+FE0F), against the claim that a client prints a ref as it is. Fixed: the claim is now that a printed ref carries no terminal control sequence, and the doc says two refs that look the same can differ.
  Held: three switches during a tool run, no sequence gap, entries between the call and its result, resume restores the last one, the running turn stays on its model.

## Round 2 (rerun, full round: the fix touched more than one code file)

Invariant named in the briefs: a composer line is either the `/model` command or a message, never both; the argument reaches `ModelRef.parse/1` whole; `ModelRef` alone owns the bounds of a ref.

- **Simplify**: 4 findings on `run_command/4` and the split. Applied, as one change: no split at all; the TUI takes what follows `/model`, trims it, and hands it to `set_model/2`. Skipped as false: "`String.split/1` is identical" (it does not split on U+00A0, reproduced in round 1).
- **Standards**: no hard violation, 6 judgement calls kept. Fixed: the `persist/2` comment and the "Core parses it once" moduledoc line were stale; `resolve_model/2` moved below the public functions.
- **Spec and failure-path, confirmed, same mechanism, 3**: a BOM before the word or U+200B after it made the line a message (`String.trim_leading/1` strips whitespace only); a pasted tab is dropped by the input widget, so `/model<tab>a/b` arrived as `/modela/b` and was sent. With the round 1 finding this was the second round on command recognition, so the two-findings rule applied: the mechanism was replaced. A line is a command line when it starts with `/model` after any run of whitespace and category C characters, and a command line is never sent; no separator after the word gives the usage notice. Cost, stated in the doc: a prompt cannot start with `/model`.
  Held: a 1 MiB ref, 1 MiB of spaces, Alt+Enter, a rejected command keeps the composer.

## Round 3 (rerun, full round: more than one code file, and the two-findings rule)

Invariant named in the briefs: a line that starts with `/model`, after whitespace and category C characters, is never sent as a message. The briefs, the code comment, and the TUI bullet also said "nothing that looks like the command on screen reaches the model". That second sentence was the author's and it was wrong.

- **Simplify**: nothing applied. Skipped as false: "the guard `when head < byte_size(text)` is dead" (it gives `/modelx` the usage notice). Skipped, out of scope: a general `/word` dispatcher, which would make every line that starts with `/` a command (the ticket states no such decision; one command exists). Settled: the `[\s\p{C}]` class in the TUI marks the command word, the one in `ModelRef` bounds a ref; two concepts, no shared constant from core into a plugin.
- **Standards**: no hard violation. Fixed: the feature doc still said "Core parses it once"; the `persist/2` comment named `consume/3` as the guard for a model string, which `ModelRef.parse/1` is.
- **Spec and failure-path, confirmed, same finding**: lines that look like the command and are other bytes are still messages: a category C character inside the word (`/mo` U+200B `del`), an invisible character outside category C before it (U+3164, U+034F, U+FE0F), a homoglyph. No pattern closes that class, so this round patched no pattern. Fixed: the claim. The comment, the TUI bullet, and the bounds row now state the rule on bytes and its limit, with the cost (that of a typo; no trust boundary is crossed), and a test pins the limit.
  Held: the four earlier reproductions; 1 MiB and 8 MiB heads; Alt+Enter; `/model` during a running turn makes no queue entry.

## Decisions the ticket does not state

Recorded here so the Codex review and the orchestrator can judge them:

- A `model_change` event, the eleventh event type, with a nil turn id. The status bar renders from events only, so the switch needs one; `queue_update` is the precedent.
- A switch during a turn is accepted at once and the running turn keeps its model and provider ("takes effect on the next turn").
- The ref bounds live in `ModelRef.parse/1`, so they hold for `--model` and for resume too: a saved file with whitespace in its model no longer resumes. The writer never produced one.
- A prompt cannot start with `/model`.
- Open for a later decision, not built: a general `/word` command rule.

## Out of the ticket, not fixed

- `Helyx.TUI.handle_event/2` has no rescue around `ExRatatui.text_input_insert_str/2`, which raises `ArgumentError` on invalid UTF-8. A terminal paste arrives as a Rust `String`, so the path looks unreachable; it predates this diff.
