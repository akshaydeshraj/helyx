# Review: issue #35 — Edit overlap rejection, Read absolute line numbers

Scope: `lib/helyx/tool.ex`, `plugins/tool_edit`, `plugins/tool_read`, and the
tests that assert the head-truncation notice (`test/helyx/tool_test.exs`,
`plugins/model_context_default`). Ticket: #35.

## Round 1 (full: simplify, standards, spec, failure-path)

Simplify findings, applied:

- `truncate/3` duplicated the `:head` clause of `truncate/2` (flagged by all
  four agents). Fixed: `truncate/2 :head` delegates to `truncate/3`, so every
  head notice names the continuation offset. The unified notice reaches
  `model_context_default`; accepted, because those files are readable by
  offset.
- Edit's hand-rolled `binary_part` splice and the dead `scope_len` guard
  (`:binary.match/3` returns `:nomatch` on a short or empty scope; verified).

Review findings, resolved:

- **Failure-path (reproduced, blocked precommit):** `truncate/3` sat between
  the two `truncate/2` clauses; `mix compile --warnings-as-errors` failed on
  clause grouping. Fixed by moving the `:tail` clause up.
- **Standards (hard):** `window/2` used an inline `if` against the AGENTS.md
  multi-clause rule; Read's moduledoc said "cut from the tail end" and the
  description omitted the continuation offset. All fixed.
- **Standards/spec (judgement):** `String.replace` rescanned after the
  uniqueness check. Deferred to round 2 (see mechanism rule below).
- **Spec:** over-limit error could also name the file's own size. Skipped;
  the ticket asks only for the limit.

## Round 2 (full; fix > 15 lines, two code files)

Two mechanisms drew repeat findings across rounds, so the round fixed the
mechanisms, not the paths:

- **Line splitting owned twice** (round-1 efficiency and reuse, round-2 reuse
  and altitude): `window/2` split, dropped, joined; `truncate/3` split again,
  and the two splitters disagreed on the trailing terminator. Fixed: the
  offset drop moved inside `truncate/3`; `lines/1` is the only splitter.
- **Splice vs rescan** (four findings across rounds): Edit now splices with
  `binary_part/3` at the known match position.

Review findings, resolved:

- **Standards (hard):** `truncate/2` `@doc` and Read's "from the start"
  description under-stated the new behavior. Fixed, with a doc line for the
  trailing-newline asymmetry of `truncate/3` windows past line 1.
- **Spec (gate):** `mix format --check-formatted` failed on reflowed test
  asserts. Fixed by formatting all touched projects.
- **Failure-path (reproduced, pre-existing):** a single line over the
  51,200-byte cap is cut, the notice claims the line was fully shown, and the
  remainder is unreachable by any offset. Locked in by an existing
  `tool_test.exs` case and out of the ticket's scope; filed as issue #50.

Skipped with rationale:

- The `:head` atom in `truncate/3` (a constant argument): kept, it mirrors
  `truncate/2` and keeps which-end explicit at call sites.
- Moving the notice text out of the shared helper: would reintroduce the
  duplicated head clause; the hint is truthful for every current caller.
- Restoring the match count in Edit's error: the ticket forbids it.

## Round 3 (full; round-2 fix touched two code files)

Simplify: clean apart from doc leftovers, applied (the bounds row in
`docs/features/coding-agent.md` had the truncation direction backwards and
omitted the continuation offset; `max_bytes/0` doc now names both arities).
Skipped: collapsing the three-hop offset default (the guarded clause is the
documented standard) and the `:tail` `length/1` walk on the `:all` path (same
class as the accepted `length(shown)` trade-off).

Review: no findings on any axis. Standards verified clause adjacency, single
splitter, and doc accuracy; spec re-ran every acceptance criterion and the
gates (format, Credo strict, all suites green); failure-path re-reproduced
both ticket cases plus multibyte and byte-cap chaining with no gap and no
repeat. One observation, pre-existing and self-correcting: a non-integer
`offset` falls through to a head read; the notice still reports the lines
actually shown. Not fixed here.
